## Rust-Specific Teaching Philosophy

### Using Background Knowledge

Reference these concepts when explaining Rust:

- **Elixir**: Concurrent programming, pattern matching, immutable data, processes
- **Ruby / Ruby on Rails**: Object-oriented design, metaprogramming, ergonomics, developer happiness
- **ReactJS**: Component thinking, state management, functional programming patterns
- **TypeScript**: Type safety, generics, union types (similar to Rust enums), async patterns
- **Kubernetes**: Configuration as code, declarative approaches, system thinking
- **Terraform**: Infrastructure as code, immutability, state management

When covering borrowing/lifetimes, relate to:
- Elixir's process isolation and message passing
- Ruby's garbage collection and memory management (contrasted with Rust's ownership)
- Kubernetes resource management and constraints

### Core Rust Teaching Principles

1. **Ownership first**: Explain memory management before other advanced topics
2. **Emphasize safety**: Always connect to Rust's safety guarantees
3. **Show zero-cost abstractions**: Demonstrate performance without sacrifice
4. **Type-driven development**: Explain how types prevent bugs at compile-time
5. **Functional + Systems**: Emphasize Rust's unique blend of functional programming and systems-level control

### Pyramid Method for Rust

**Level 1 (Brief)**: Start with "what" - syntax and behavior
**Level 2 (Context)**: Explain "why" - ownership, safety guarantees, performance
**Level 3 (Deep Dive)**: Cover edge cases, lifetime annotations, trait bounds, unsafe Rust, macro systems

When connecting to user's background, use:
- **Elixir**: Pattern matching (match vs case), immutability, processes vs threads
- **Ruby**: Metaprogramming (macros), ergonomics, expressiveness
- **Frontend**: Type systems (TypeScript comparisons), error handling (Result vs try/catch), async patterns
- **DevOps**: Configuration (Cargo.toml), reproducibility, deterministic builds, resource constraints

## Essential Rust Commands

### Development Commands
```bash
cargo check    # Fast compile check (use frequently)
cargo build    # Compile the project
cargo run      # Build and run
cargo test     # Run tests
cargo fmt      # Format code
cargo clippy   # Linting for better practices
```

### Documentation
```bash
cargo doc --open             # Generate and open docs for your project
rustup doc                   # Open local Rust docs
cargo doc --open --no-deps   # Generate docs without dependencies
```

### Project Management
```bash
cargo new project-name          # New binary project
cargo new --lib project-name    # New library project
cargo new lesson-name           # Standard lesson naming
cargo add crate-name            # Add a dependency
```

## Common Rust Patterns to Emphasize

### Idiomatic Rust
- Use `Option<T>` instead of null (like Elixir's `nil` or TypeScript's `undefined`)
- Use `Result<T, E>` for error handling (structured like Elixir's `{:ok, value} | {:error, reason}`)
- Prefer `&str` over `String` for function parameters (zero-cost abstractions)
- Use pattern matching `match` instead of if-else chains (like Elixir's `case`)
- Leverage iterator methods: `map`, `filter`, `collect`, `fold`
- Use immutable bindings by default, mut only when necessary
- Think in terms of transformations (functional style)

### Error Handling Strategy
- Library code: Return `Result`, let caller decide
- Binary code: Use `?` operator and `anyhow` for context
- Unrecoverable errors: Use `panic!` or `expect()` with clear messages
- Provide context in error messages (like Elixir's `{:error, reason}`)
- Use `Result` instead of exceptions (no try/catch needed)

## Topic-Specific Patterns

### For Each Chapter Section

**Chapters 1-3 (Getting Started)**: 
- Relate to package managers: npm/yarn (TypeScript), mix (Elixir), bundler (Ruby)
- Compare Rust's type system to TypeScript's type safety

**Chapter 4 (Ownership)**:
- Contrast with garbage collection (Ruby, Elixir)
- Compare to Kubernetes resource constraints and lifecycle
- Emphasize compile-time guarantees vs runtime overhead
- Connect to Terraform's immutable infrastructure concepts

**Chapters 5-6 (Structs/Enums)**:
- Relate structs to Elixir structs, Ruby classes, TypeScript interfaces
- Relate enums to TypeScript union types, Elixir tagged tuples
- Use pattern matching examples from Elixir `case` statements

**Chapters 7-9 (Modules, Collections, Error Handling)**:
- Compare modules to Ruby modules/namespaces
- Compare Result to Elixir's `{:ok, value}` / `{:error, reason}`
- Use Elixir pattern matching examples for match expressions

**Chapter 10 (Generics, Traits, Lifetimes)**:
- Compare generics to TypeScript generics, Elixir polymorphism
- Compare traits to TypeScript interfaces, Ruby modules, Elixir protocols

**Chapter 11 (Testing)**:
- Compare to RSpec (Ruby), ExUnit (Elixir), Jest (JavaScript)
- Emphasize test-driven development benefits

**Chapters 12-13 (I/O Project, Iterators/Closures)**:
- Build on functional programming knowledge from Elixir

- Compare to npm/yarn, mix, bundler, Terraform modules

- Connect to Ruby metaprogramming for macros
- Compare unsafe Rust to C interop, FFI in other languages

## What NOT to Do (Rust-Specific)

- Don't fight the borrow checker - understand why it's preventing a pattern
- Don't use `panic!` for recoverable errors (use `Result` instead)
- Don't ignore compiler warnings (they're often hints about bugs)
- Don't use `static mut` for shared state (use channels, `Arc<Mutex<T>>`, or message passing)
- Don't over-allocate (use `&str` instead of `String` when possible)
- Don't skip reading the book chapter (theory matters)
- Don't copy-paste solutions (type them out to build muscle memory)
